# Dataset authorship, provenance and publication gate

**Status: no dataset has been exported or distributed by this repository.**

## Author's statement

On **2026-11-10**, the project maintainer stated that the dataset underlying VirgoStars `sinodi`, `moto_pianeti` and `ingresso_segni` is **entirely their own and generated by their own algorithms**. This is recorded as the maintainer's authorship and origin declaration; it has **not been independently verified** against source records, dependencies or licensing documentation. Do not replace it with claims that NASA/JPL/Swiss Ephemeris datasets were used, or with a contrary assertion without evidence.

## Authorship vs. data licensing

Ownership/originality of the source data does **not** by itself specify third-party redistribution rights. **Dataset distribution license: TO BE CHOSEN and approved by maintainer before publishing binaries.** Do not assume CPAL-1.0 (the code license) grants rights to the separately released VSEPH dataset. Open-data licenses such as CC BY 4.0 may be evaluated separately, but none has been selected here.

If a maintainer chooses a dataset license, record: SPDX or legal text, scope (event data, metadata, derived exports), attribution URL, modification/distribution conditions, dataset version/date and rights confirmation. Avoid embedding a restrictive or ambiguous EULA in an otherwise open dataset.

## Minimum source-snapshot audit

For each data family and body, use a **read-only repeatable snapshot** and collect:
- count; UTC min/max; distinct body/field values; source table schema and timestamp data types;
- duplicate timestamps/body keys, ordering, sign ranges (0..11), direction codes (r/d);
- phase extras NULL / array size distribution, monotonicity, max duration per body, phase-code mapping;
- unusual gaps, suspicious event frequency and outlier timestamps;
- evidence about SQL timestamp-without-time-zone representing UTC, incl. old records;
- generator/method version and any third-party dependency declarations;
- cryptographic digest of canonical normalized export + file + manifest;
- owner approval and data-license selection before upload to public releases.

Do not log secrets, DB URLs, source subject identities, Telegram text or message references.

## Export and storage

Export is development tooling, never part of the published runtime. Do not commit production data dumps or generated VSEPH files before explicit owner approval. Prefer separate release assets with signed checksums, plus small **synthetic** fixture datasets committed to the source tree.

Never claim “all astronomical history” or “full precision” without verified per-body temporal coverage, error estimates and known-gap manifest. Manifest must show **reported vs audited** metadata and clearly label pending fields.

## Time conventions

- `sinodi.dataora`: `TIMESTAMPTZ`, normalized by PostgreSQL to an instant.
- `moto_pianeti.dataora` and `ingresso_segni.dataora`: `TIMESTAMP WITHOUT TIME ZONE`, treated by current app as UTC by convention. Confirm this convention before exporting rather than depending on the exporter machine's TZ.
- Preserve exact source timestamp precision (microseconds if present) even if many source records have whole seconds. Timestamp precision does not imply positional accuracy.
- Be explicit that leap-second/TT/TDB provenance is not established by a SQL timestamp.

## Release clearance

A dataset may be released **only after** rights/license decision, source snapshot audit, coverage/gap manifest, parity tests, checksum validation, and maintainer approval. Until then published documentation must say **no dataset available**.
